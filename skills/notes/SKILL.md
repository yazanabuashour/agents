---
name: notes
description: Use when consulting personal notes to answer a question, preserving durable context, or finding a note link for a task.
---

Canonical Markdown owns durable knowledge; task systems own task state.

- Use `~/notes` when available. Read its `AGENTS.md`; start at `_index.md` or
  search for relevant existing context before authoring a note.
- Save useful decisions, constraints, evidence, and outcomes as they emerge.
  Update the canonical note rather than creating a near-duplicate; preserve
  stable IDs, issued URLs, and heading fragments.
- For task links, preserve supplied URLs or use verified published page and
  heading URLs. Local paths are not cross-device reader links. Use existing
  publication configuration when available; do not invent a host or URL.
- Without a local vault, use only supplied links or explicitly authorized
  remote note access. If neither is available, report the limitation and keep
  essential context in the result or task. Do not create, clone, or mount a
  vault, or configure access, merely to satisfy this workflow.
